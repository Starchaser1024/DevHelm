# 服务发布与生产故障响应手册（Engineering Runbook）

## 变更分级与发布窗口

所有进入生产环境的代码变更按影响半径划分为三级：

- **L1（常规变更）**：仅涉及前端静态交互、非核心异步任务或只读查询接口，测试覆盖率达标且 PR Review 通过后可在工作日 `10:00–18:00` 灰度上线。
- **L2（关键链路变更）**：涉及鉴权、Webhook 验签、GitHub 同步调度、RAG 检索管线或模型调用网关，必须附带回滚预案并在预发环境完成回归评测。
- **L3（高风险架构/存储变更）**：涉及 PostgreSQL 表结构迁移（Alembic）、Milvus 集合 Schema 变更或 Token 加密算法调整，必须采用“先扩列兼容、双读双写、再切流清理”的两阶段发布策略，禁止在周五及节假日前一日执行。

## 金丝雀发布与自动止损门槛

服务采用 `5% -> 25% -> 100%` 三阶段滚动发布，每个阶段至少观察 15 分钟。出现以下任一指标异常时必须立即暂停放量并执行回滚：

1. `/api/chat` 或 `/api/rag/{repo_id}/ask` 的 `5xx` 错误率连续 3 分钟超过 `1.0%`。
2. SSE 首字节延迟（TTFB）`P95 > 4.5s`，或端到端工具调用超时率超过 `3.0%`。
3. Milvus 检索状态降级为 `degraded` 且非预期触发，或数据库连接池活跃连接占用率超过 `85%`。

## 数据库迁移与索引重建规范

- 表结构变更统一通过 `alembic revision --autogenerate` 生成迁移脚本，并由至少一名后端 Owner 审查锁表风险。
- 新增非空字段必须拆分为两步：先新增可空列并回填历史数据，待旧实例全部下线后再补充约束。
- 当切片策略（Chunking）或 Embedding 模型升级时，需在低峰期调用 `POST /api/rag/{repo_id}/reindex` 重建仓库向量索引，并通过固定 RAGAS 基准集验证 `Faithfulness >= 0.90`、`Context Recall >= 0.80`。

## 生产故障响应（Incident Response）

- **P0（核心服务不可用 / 数据安全风险）**：值班工程师（On-call）须在 **5 分钟**内响应，**15 分钟**内拉起应急群并指定 Incident Commander（IC），每 **30 分钟**同步一次止损进展。优先通过特性开关（Feature Flag）或版本回滚恢复服务，严禁在未止损前在线调试根因。
- **P1（局部功能受损 / 性能显著退化）**：须在 **15 分钟**内响应，**1 小时**内完成降级或修复（例如将混合检索临时降级为 PostgreSQL 词法检索，或关闭后台自动同步任务）。
- **复盘要求（Postmortem）**：P0/P1 事故恢复后 **48 小时**内输出无指责复盘文档，明确根因链路、检测盲区、监控补强项及自动化回归用例，复盘结论经审核后沉淀至项目长期记忆与知识库。
